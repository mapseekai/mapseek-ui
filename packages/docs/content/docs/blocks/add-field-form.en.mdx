AddFieldForm is the controlled body for adding an attribute field. It handles field name, type, type-aware default value, nullable, and description inputs; dialog chrome, footer submission, schema writes, and validation policy stay with the caller.

## Usage

Initialize from `EMPTY_ADD_FIELD`, pass the allowed `fieldTypes`, and store the complete draft in `onChange`. Supported types are `text`, `integer`, `float`, `boolean`, and `date`; their defaults use text, number (with a `0.1` float step), a Yes/No select, or the Calendar date picker initialized to the current date. Submit actions usually live in an outer Dialog or Drawer and check `value.name` and duplicate keys.

## Public Exports and Props

Exports include `AddFieldForm`, `EMPTY_ADD_FIELD`, `AddFieldDefaultValue`, `AddFieldType`, `AddFieldFormProps`, `AddFieldFormLabels`, `AddFieldValue`, and `FieldTypeOption`. Key props are `value`, `onChange`, `fieldTypes`, `labels`, and `className`; `FieldTypeOption` provides a label and icon for each supported type.

## States and Validation

The block does not submit, show errors, or deduplicate names by itself. It keeps every field editable and reports changes to the caller. The demo status shows how an outer shell can turn a draft into submit availability.

## Accessibility

Fields use readable labels and input controls. Type choices are buttons; the date picker pairs a focusable trigger with Calendar, and nullable is a checkbox paired with a label. Outer submit UI should expose error text, dialog title, description, and disabled submit state to keyboard and screen reader users.
