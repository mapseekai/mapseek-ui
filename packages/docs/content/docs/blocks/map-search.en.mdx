MapSearch combines place lookup and longitude/latitude lookup in a collapsible map-search panel. The block owns inputs, results, async state, and coordinate validation while callers provide geocoding and map-flight behavior through callbacks.

## Callback Contract

`onSearchPlace(keyword, signal)` returns place results. New requests abort older requests, so the data source should honor the `AbortSignal`. Selecting a result calls `onSelectPlace(place)`, the place locate action calls `onLocatePlace(keyword)`, and valid coordinates reach the map application through `onLocateCoordinates({ longitude, latitude })`.

```tsx
<MapSearch
  onSearchPlace={(keyword, signal) => geocoder.search(keyword, { signal })}
  onSelectPlace={(place) => map.flyTo([place.longitude, place.latitude])}
  onLocatePlace={(keyword) => locateKeyword(keyword)}
  onLocateCoordinates={({ longitude, latitude }) => map.flyTo([longitude, latitude])}
/>
```

## State and Validation

Empty keywords do not start a lookup, and the default debounce is 300ms. Loading, empty, search-error, and locate-error states provide readable feedback. Longitude is limited to `[-180, 180]` and latitude to `[-90, 90]`; parseable out-of-range values report immediately, while empty and non-number values report after blur or a locate attempt. Switching tabs or collapsing preserves current input. Place and coordinate actions use compact icon buttons and stay on the same row as their fields, preventing localized labels from squeezing the inputs.

## Localization and Accessibility

The block ships with Chinese defaults and accepts `labels: Partial<MapSearchLabels>` overrides. Place results follow standard Combobox behavior: use Arrow keys or Home/End to browse, Enter to select, and Escape to close the popup. Tabs support keyboard switching, icon-only actions expose accessible names and tooltips, validation connects `aria-invalid` fields to descriptive errors, and the locate button retains its localized accessible name while loading.
