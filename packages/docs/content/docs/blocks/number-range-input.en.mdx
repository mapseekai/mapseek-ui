## Usage

Pass controlled `value`, `min`, `max`, `step`, and `onChange`. Users can drag the slider or type directly; on blur, the component normalizes display according to range and step.

When `value` is omitted, `defaultValue` supplies a real uncontrolled initial value. In controlled mode, `value={undefined}` clears the numeric value; the caller decides whether that state should show a required error.

## Public Exports and Props

Exports include `NumberRangeInput` and `NumberRangeInputProps`. Key props are `value`, `defaultValue`, `min`, `max`, `step`, `onChange`, `required`, `disabled`, `name`, `id`, `autoComplete`, `aria-label`, `aria-labelledby`, `aria-describedby`, `sliderAriaLabel`, `className`, `sliderClassName`, and `inputClassName`.

## States and Validation

The component stores in-progress edit text and commits valid values through `onChange`. Slider values clamp to min/max and round to step precision; decimal steps constrain displayed precision. It merges internal editing errors with caller-provided `aria-invalid`; callers supply form help and error copy through `FieldDescription` and `FieldError`, linked with `aria-describedby`.

The numeric `Input` uses the standard 32px height. Slider thumb and pointer-target geometry are unchanged.

## Accessibility

Every instance needs a non-blank accessible name. Without a visible label, pass `aria-label`; it names the numeric input and defaults to the Slider thumb name. With a visible `FieldLabel`, pass `aria-labelledby` pointing to the label ID and **also provide** a non-blank `sliderAriaLabel` for the Slider thumb.

Give the numeric input a stable `id`, link help and errors with `aria-describedby`, and pass `autoComplete` where appropriate. Both slider and number input support keyboard operation; callers own `FieldDescription`, `FieldError`, localized copy, and external `aria-invalid` state.
