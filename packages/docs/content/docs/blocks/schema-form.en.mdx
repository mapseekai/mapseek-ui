SchemaForm is a schema-driven form body for number, text, select, and multiselect fields. The caller converts domain fields into those primitive types and owns values, validation, and submission.

## Usage

`values` is the current controlled source; use `seedSchemaFormValues(fields)` only to initialize or reset it. Pass `fields`, `values`, and `onChange` to `SchemaForm`; submit buttons usually read `isSchemaFormValid(fields, values)` to decide whether the operation can run.

## Public Exports and Props

Exports include `SchemaForm`, `seedSchemaFormValues`, `isSchemaFormValid`, `SchemaFormField`, `SchemaFormOption`, and `SchemaFormProps`. Key props are `fields`, `values`, `onChange`, `errors`, `labels`, `idPrefix`, and `className`.

Fields can specify `name`, `autoComplete`, and text `spellCheck`; an omitted name uses the field key, while number/text default to `autoComplete="off"`. `errors` is caller-owned localized error text by field key, and `labels.emptyOptions` provides the global empty-option fallback copy.

## States and Validation

The component stores no business state. Number values must be finite and honor `min`/`max`; multiselect honors `min` even when the field is optional. Empty select and multiselect options use `field.emptyHint`, falling back to `labels.emptyOptions`.

`seedSchemaFormValues` fills field defaults for reset; subsequent external value updates immediately render in the controlled controls. Every instance generates unique field IDs, while `idPrefix` is available when callers need a stable prefix.

## Accessibility

Every field has a Label associated with its control. `required` renders an asterisk and native or ARIA required semantics; `errors` marks the control invalid and links it to a field error with `role="alert"`. Callers own localized errors and can add an error summary near submission.
