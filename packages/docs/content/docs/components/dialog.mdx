Dialog 用于短流程、确认和局部表单。它通过 portal 渲染到文档根层，避免被示例容器、滚动面板或 `overflow` 裁切，同时保留焦点陷阱、Escape 关闭和触发器焦点返回。

## 结构

`DialogContent` 是浮层容器，负责 portal、遮罩、最大宽度、16px 内边距和区块间距。短内容可以直接传入 `title` 与 `description`；复杂标题使用 `DialogHeader`、`DialogTitle` 和 `DialogDescription` 组合。

`DialogBody` 承载正文，长内容需要给 body 设置滚动边界。`DialogFooter` 在窄屏纵向排列，在 `sm` 以上横向右对齐。业务示例不需要在 header 或 footer 上重复补内边距。

## 可访问标题

每个 Dialog 必须拥有可读标题。优先通过 `DialogContent title` 或 `DialogTitle` 提供标题；关闭按钮包含屏幕阅读器文本。不要把标题只做成装饰图标或只依赖占位文本。

## Dialog 与 Sheet

Dialog 适合短确认、少量字段和必须阻塞当前流程的任务。长表单、详情阅读、批量编辑和需要频繁滚动的内容应使用 Sheet，让用户保留更多上下文和更稳定的滚动空间。

## 无障碍

触发按钮应清楚说明会打开什么。关闭、取消、保存和危险操作都应使用真实 `button` 或 `DialogClose`。不要在 Dialog 内隐藏主要说明，也不要用颜色作为唯一状态提示。
